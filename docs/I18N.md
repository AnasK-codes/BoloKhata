# Interface languages (i18n)

The app's on-screen text can be shown in **Hinglish** (default for Indian browsers), **हिन्दी** and **English**. This is only the interface language. It is separate from:

- **What the shopkeeper speaks** (STT parsing, the gateway's rules and dialect hints): unchanged.
- **The spoken readback** (TTS text built by the gateway, `draft.replyText`) and **bill warnings** (`draft.warnings`): these arrive from the gateway as Hinglish text and are shown as they are. Translating them needs warning codes in the protocol (not done).
- **User data:** item names, customer names, the transcript, amounts and the receipt footer the shop typed. Never translated.

Printed thermal receipts and WhatsApp reminder messages go to customers and stay in their current wording. They need a separate "customer language" setting if wanted.

## How it works

- `apps/web/src/lib/i18n/locales/en.ts` is the **source of truth**: about 430 stable keys (`area.thing`). `hi.ts` and `hi-Latn.ts` are typed `Messages`, so a missing or misspelt key fails `pnpm typecheck`.
- `t(key, params)` fills `{placeholders}`. A message can be a set of plural forms (`{ one, other }`) chosen by `{count}` with `Intl.PluralRules` for that language (Hindi treats 0 and 1 as "one"). Sentences are always whole messages, never glued from fragments, so word order belongs to the translator.
- Money keeps the one shared format (`rupees()`, Indian grouping `₹1,25,000`). Dates use the language's locale (`formatDateFor`). Unit codes (`kg`, `packet`) are stored as is; only their display is translated (`components/voice/units.ts`).
- All dictionaries ship in the bundle (no network call), so switching works offline and in the installed PWA. The choice is saved in `localStorage` (`bolbill.locale.v1`), like the other settings.
- First launch: saved choice → browser language (`hi*` → हिन्दी, any other `*-IN` → Hinglish, `en*` → English) → Hinglish.
- `LocaleSync` (in the root layout) applies the language in a layout effect, before first paint, and keeps `<html lang>` in step (`hi`, `hi-Latn`, `en-IN`). CSS keyed on `html[lang='hi']` gives Devanagari taller lines and normal letter-spacing, which keeps matras unclipped and the headline stroke unbroken.
- Components subscribe with `useT()`. Nothing on the audio path reads the language, so a switch in the middle of a turn re-renders text only. This was checked in the browser: switching while recording kept the turn going, and it completed normally.

## Adding a language (for example Marathi)

1. Copy `locales/hi.ts` to `locales/mr.ts`, translate every value, and set `meta` (`id: 'mr'`, `nativeName: 'मराठी'`, `htmlLang: 'mr'`, `intlLocale: 'mr-IN'`, `status: 'needs-review'` until a native speaker checks it).
2. Add it to `LOCALES` in `lib/i18n/index.ts` (one line). The picker, persistence and `<html lang>` follow automatically.
3. Run `pnpm --filter @bolbill/web test`. The tests fail on a missing or extra key, a placeholder that differs from English, or a plural form the language needs but lacks.
4. If the script needs its own font metrics (Tamil, Bengali), add an `html[lang='…']` block next to the Hindi one in `globals.css`.

## Checks

`src/lib/i18n/i18n.test.ts` covers:

- **Key and placeholder parity** between every language and English.
- **Plural forms** each language's rules need.
- **No empty strings.**
- **No dead keys:** every key is used somewhere in the app.
- **Interpolation and plurals.**
- **Default selection, persistence and blocked storage.**
- **No hard-coded interface text:** a TypeScript-parser scan of every `.tsx` file flags JSX text, `aria-label`/`placeholder`/`title`/`alt` literals and capitalised string literals (with a self-test proving it catches planted text). Developer lab pages under `app/dev` are excluded. A line can opt out with an `i18n-ignore:` comment and a reason; two do (an internal developer error and the static page metadata).

## Known gaps

- Gateway-built text (`replyText`, `warnings`, `connection.message` in limited/blocked notices) is not translated.
- The `/dev/audio` and `/dev/turn` lab pages stay in English (developer tools, never in the demo).
- The browser tab title and PWA manifest name stay "Bol-Bill" in every language.
